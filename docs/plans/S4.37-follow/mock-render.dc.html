Contracts
C1 · FOLLOW STATE MACHINE
Inherited from S4.36 and restated: not_following → pending → following. Tap is optimistic — pill flips immediately, request fires in background. On failure: revert + toast "Couldn't follow @handle". Tapping Following unfollows with no confirm dialog, same optimistic pattern. Pending taps are ignored; follow is idempotent server-side.
C2 · PILL TREATMENTS
Follow = filled #EA580C, white 13.5/700 label. Following = white fill, 1px #E7E5E4 border, ink label, leading 14px check glyph. Both: height 40, radius 999, press scale 0.96. No width jump — the pill spans the content column in both states.
C3 · LIST PAGINATION + COUNT
Follower/Following lists: infinite scroll, cursor pages of 20, fetch at 5 rows from end. Count line "{n} followers" / "{n} following" 13/600 muted under the title. Rows are plain — 44px avatar r22, name 15/700, handle 13 muted, trailing chevron #D6D3D1; no follow button in rows (the pill lives on the profile). Tap opens that traveler's profile.
C4 · STAT-CELL TAPS
Followers and Following cells are pressable on both the traveler's own Profile tab and any public profile — each pushes the matching list screen (1a/1b). Published and Destinations cells stay inert. Counts render real numbers; the em dashes shipped in S4.36 are retired.
C5 · FOLLOWS-YOU CHIP
Shown next to the "@handle · #N" meta line when the profile's owner follows the viewer. Read-only, quiet: #F5F5F4 well, 11/700 muted label, radius 999. Never on your own profile, never a tap target, and it does not change the pill's treatment.
C6 · HOME FILTER SEMANTICS
Chip row under the Home header: All (default) · Following. Cold start always lands on All; the selection is remembered only while the app runs — never persisted. Following shows only postcards from travelers you follow; feed cards themselves are unchanged. Empty per 3b — both when following nobody and when follows have no posts.
C7 · OFFLINE
Profile header (avatar, name, stats) renders from cache when offline. Follower/Following lists and search results show an inline Retry row instead of a blank screen. Follow taps while offline fail fast into the revert + toast path — no queued mutations.
C8 · EXECUTED-SEARCH SEMANTICS
Submitting a query always lands on the combined results screen (4). The People group renders whenever at least one person matches — the old "only if more than 3" rule is gone; same for "See all people" in the suggestions overlay. Fences unchanged: min 2 chars, no empty-query browse, match on handle + display name only, never email. People cap 3 + "See all people" → full People results; trips render below, unchanged.
Motion — M1–M4 (live in the frames)
M1 · PILL CROSSFADE
Fill, border, and label crossfade ~160ms ease between states; check glyph fades with the label swap. Press scale 0.96 at 120ms. Revert-on-failure reuses the same crossfade back — no bounce, no confetti.
M2 · LIST CASCADE
Follower/Following rows and search-result rows: fade + 6px rise, 200ms ease, 40ms stagger, first 8 rows only. Later pages append unanimated — motion marks arrival, not pagination.
M3 · CHIP SWITCH
All ↔ Following: chip fill/label transitions 160ms; incoming feed panel fades + rises 8px over 200ms cubic-bezier(.2,0,0,1). Outgoing panel is removed, not animated — content never overlaps.
M4 · REDUCE MOTION
prefers-reduced-motion: all translates and staggers drop; every state change becomes a plain 120ms opacity swap. Press-scale removed. Nothing in this spec conveys meaning through motion alone.
