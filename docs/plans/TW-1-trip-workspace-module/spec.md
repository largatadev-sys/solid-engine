# TW-1 — The Trip Workspace module: the god module's trip half moves into `trip`

**Status:** BUILT 2026-09-08 — the record is the ten tickets' Comments in `issues/`, and ticket 10 is the gate. ## Problem Statement

The trip's code lives in the wrong place. `com.largata.itinerary` is the 135-file god module the strangler is digesting: its content half moved out at CM-1 and CM-2, but its trip half — the record, the plan, the editing session, the cover, the dump, the lifecycle — is still there, flat, with 13 controllers in one folder and 42 DTOs in another, named with the glossary's word for the *other* object. The `trip` module that postcard and publication depend on is a raw-SQL facade over that half's tables, alive by a strangler waiver whose dissolution condition is this story. Workspace and membership, which the trip cannot be created without, are two more packages that reach into it and are reached into. Nothing can be moved alone, nothing is sealed, and the only guard that holds the line is a regex that forbids the new world from naming the old.

## Solution

Move the trip half into `com.largata.trip` as one bounded context — trip, plan, dump, editing, history, cover, workspace, ownership, fork — in feature slices with an `api` the other modules import and nothing else, then give the moved types the Trip names the founder's model calls for. Retire the facade: its reads become the api's implementations over the module's own repositories. Move the two packages that are welded to the trip inside it. Let the old package's content half keep reaching in under a named, counted exemption that dies with the package at CM-5. Change no path, no table and no test assertion; the grammar already moved at CM-3, and the twins move with their controllers.

## User Stories

1. As a traveler on any app version, I want every workspace screen to keep working through this story, so that a refactor I cannot see costs me nothing.
2. As a traveler editing a plan with a co-traveler, I want the editing-session and plan-saved frames to arrive as they do today, so that the live workspace is untouched by where the code lives.
3. As a member accepting an invitation, I want admission to stay one act with the invitation's status flip, so that a failed admission never leaves an accepted invitation with no member.
4. As a trip owner archiving a trip, I want pending invitations voided and the ownership offer withdrawn as today, so that an archived trip stops recruiting.
5. As the next agent, I want the trip module to have one door — its `api` and its refusals — and a guard that fails the build on any other import, so that I cannot reach into it by accident.
6. As the next agent, I want the trip's code in feature slices whose folder says what the code is about, and named for what it is, so that I find the editing session under `editing/` and a `TripService` that serves trips.
7. As the next agent, I want the old-world integration tests to pass with package, import and renamed-symbol edits only and zero assertion edits, proven by a script rather than a claim, so that the move is verified by the suites it did not write.
8. As the next agent, I want the guards' temporary migration windows gone before the PR, with a test that says so, so that a branch-local exemption cannot outlive the branch.
9. As the founder, I want the old package left standing with its content half until CM-5, so that decommissioning is a decision taken on a verified module and not a side effect of a refactor.
10. As the founder, I want every deferral named with its trigger, so that the schema move and the foreign-key drops are decisions on the record rather than things forgotten.

## Implementation Decisions

**The rulings, from the grilling record.** The unit is the Trip Workspace: workspace and membership absorb (planning pass, upheld). The move is once, and the old paths are adapters by construction — one implementation, both roots (planning pass, upheld). The trip half's Java types take Trip names in a separate commit after the relocation; the table and the old wire keep the historical noun until CM-5 (round 1 Q2, round 3 Q2). The content half of the old package stays under the design's legacy exemption, counted and dissolving at CM-5 (round 3 Q1 — reversing the planning pass, because the founder's model made the api it would have consumed throwaway). Layout is feature slices with the layer as filename suffix (round 2 Q2); the guard is the allowlist plus the meta-test (round 2 Q3); events are Spring AFTER_COMMIT with `fallbackExecution`, logged on failure (round 2 Q4); `exception/` is published surface. Destruction keeps its five foreign deletes under a narrowed waiver (round 1 Q8). Nothing in the database moves or drops (round 1 Q9). Fork moves in whole (round 1 Q10, round 2 Q6). `TripsTopic` becomes a listener in `ws` (round 1 Q11). Admission stays one transaction (round 2 Q7). The gate's proof is a script that diffs assertion lines (round 1 Q14). The move is sliced behind branch-local windows (planning pass, carried).

**The layout — nine feature slices, one `api`, then the rename.** Measured on the files that move: `trip/` 25 · `plan/` 34 · `dump/` 5 · `editing/` 15 · `history/` 4 · `cover/` 2 · `workspace/` 11 · `ownership/` 8 · `fork/` 4 · `validation/` 6 (the seven DTO validators, measured as used only by trip's DTOs, so `common` is not needed). `api/` holds `TripApi`, `PlanApi`, `MembershipApi`, CM-1's five records kept by name, the view records, and the six events; `exception/` holds only what an outside caller catches. Controllers live inside their slice carrying both roots from CM-3. Visibility widens where a slice line is crossed and the ArchUnit guard becomes the seal — the price `refactor(postcard)` paid at CM-2. **The rename is its own commit after the relocation**, so the move commit is a pure move the review can read as one: `Itinerary` → `Trip`, `ItineraryService` → `TripService` (the facade of that name having retired first), `ItineraryController` → `TripController`, `ItineraryResponse` → `TripResponse` (CM-1's dark record of that name having retired at CM-3), `ItineraryState` absorbed by `TripLifecycle` (same three names, same `wireName()`, storage unchanged and pinned). The `itinerary` table and every `/v1/itineraries` path are untouched.

**The api, in three interfaces, no god service.** `TripApi` (facts, teasers, titles, state, frozen, share-card version), `PlanApi` (the plan, a day, an activity, an activity snapshot), `MembershipApi` (membership, roster, owner, `admit`, workspace ids, archived state, trips in sight) — each implemented by the slice that owns the answer; the ten existing services stay ten. Every outside consumer moves to the api: postcard and publication off the facade, invitation and join off `ItineraryService` and `WorkspaceService`, poll and ws off `WorkspaceService`. The reads the content half would have needed (the published-among and showcase reads, discovery's nine native queries) are **not** published: that half reaches in under the exemption and is deleted at CM-5.

**The legacy exemption, exact.** `TripModuleBoundaryTest` names `com.largata.itinerary..` as the one permitted consumer of trip internals, with a sabotage check that the predicate selects more than thirty classes and a message naming CM-5 as its dissolution. Trip's internals stay `public` for that reason alone. The eight staying files that reach in today — the old diary entries, the live published projection, discovery, the feed, the profile readers — are not rewritten.

**Events, and the transport that stops being a dependency.** Six events in `trip.api`: `MembershipArrived` (from invitation, gaining `tripId`), `MembershipEnded` (from membership), `TripArchived` and `TripUnarchived` (new — they replace the archive act's direct call into invitation with an `ArchiveVoidsInvitations` listener there, AFTER_COMMIT, which runs in the committing thread before the response so the contract test holds unedited), `EditingSessionChanged` and `PlanSaved` (new — `TripsTopic` imports `ws.EventFanout`, which trip may not name, so trip publishes and a `ws/TripsTopicListener` broadcasts on the same topic with the same type strings and field order; the frames are byte-identical and the unedited ws tests prove it). ADR-030 decision 3 as written.

**The facade retires; destruction keeps its reach.** The facade's reads become the api's repository-backed implementations. `destroy` moves verbatim into a `TripDestructionService` and keeps its five deletes on other modules' tables: an event-driven destruction is impossible before the FK drops (invitation, poll and join carry `NOT NULL REFERENCES workspace`) and the one-transaction contract is pinned. This is the one place trip names another module's table after this story, recorded as debt with the FK-drop story as trigger. The guard's exemption that named the facade is dropped. Publication's `markPublished` write stays as CM-5's bridge and is recorded, not rewired.

**Deferred, recorded, each with a trigger.** The schema move (`SET SCHEMA trip`): no named schema exists, and the design's own measured `pg_dump` trap applies to every inbound key the day one does — trigger the FK-drop story or the first extraction rehearsal. The FK drops: each needs a stepping test and a service replacement for the cascade — with the schema move. `MembershipApi.admit` in its own transaction: a pinned test says admission and the status flip roll back together, and an accepted invitation with no member is the worse state — recorded, not applied. No migration ships; V55 stays head.

**The order, and the windows.** Two guards bind it: the old-world regex forbids a moved file naming an unmoved package, and the ArchUnit guard forbids an outside class depending on trip internals. The cycles measured — membership imports the itinerary service, the lease service and invitation's service; the itinerary service forms the workspace; the controller needs membership; editing needs plan's repositories and plan needs editing; cover needs editing and history — leave workspace as the only slice that can move alone once `MembershipArrived` lives in `trip.api`; everything after it is welded. So: events first · workspace · the rest in dependency order, one commit each, behind two named branch-local window predicates (one per guard, sabotage-checked, deleted by the ticket that closes them with a test asserting none remains) · the rename commit · the facade retired · the guard in its final form with the meta-test · docs. About 120 files move; ≈65 test files take package, import and symbol edits.

**Mobile: nothing.** CM-3 moved the client; this story moves no path.

**Vocabulary and docs**: the glossary's Trip entry already carries the rename's meaning (ADR-037); BUILD_STATUS gets this story's row at the gate; the epic-map TW-1 line is annotated built; the design record's status line closes.

## Testing Decisions

A good test here asserts **what a path answers, what rows exist afterward, and that nothing observable moved** — never a module's internals. Five seams.

1. **The old-world suites, with zero assertion edits, proven by a script** *(the move's proof)* — the 56 integration-test classes under itinerary and the 18 under workspace and membership take package, import and renamed-symbol edits only; a thirty-line script diffs each test file's assertion lines before and after and fails on any difference; its output is the gate's headline. Hibernate's `ddl-auto: validate` at the first context boot proves the nine tables unchanged.
2. **The guards, in their final form** *(prior art: the per-module ArchUnit guards and `NewWorldBoundaryTest`)* — trip's allowlist guard with sabotage checks (module seen, front door non-empty, sealed predicate non-empty, a slice list asserted to name real packages); the legacy-exemption predicate counted; the meta-test that every module has a guard; the old-world regex shrunk twice with its positive and negative cases updated; the windows sabotage-checked while they exist and asserted absent once closed.
3. **The websocket frame tests, unedited** *(prior art: `EditingSessionEventsIT`, `TripListEventsIT`)* — they pin that the listener's frames are byte-identical to the old topic's.
4. **The grammar tests from CM-3, unedited** — the twin test and the equivalence test prove the twins moved with their controllers.
5. **Playwright, both lanes, unedited** — the migrated suites from CM-3 drive the moved code.

The connection ceiling is a constraint, not a note: 26 context signatures already sit at the container's limit, so every new integration test here reuses the shared signature and every guard that needs no context is a plain unit test. What no seam reaches and the gate closes by hand, on the LAN rung with `t1 = owner, t2 = member`: the same walk CM-3 closed, read against a backend whose log lines now come from `com.largata.trip`.

## Further Notes

- **Measured before this was written, so the order rests on facts:** four main files outside the god module import it, naming five classes; eight files of its content half reach into the trip half (`ItineraryRepository` in six, the entity in six, two repositories in two each, the service in one); `WorkspaceService` publishes invitation's event and `MembershipService` calls invitation's service — two cycles the design did not list; no raw SQL names a trip table outside itinerary and trip; the seven validators are trip-only.
- **What this story deletes, stated so it can be objected to:** only CM-1 scaffolding the real implementation replaces — the raw-SQL facade, the guard exemption that named it, `itinerary/TripsTopic` (reborn as the ws listener), and the two windows. Nothing from the old package is deleted; its trip half moves, its content half stays.
- **The story ends the two guarantees CM-1 was built around**, as the design priced: it is the first story to touch live code in the old package, and pre-existing tests are edited — package, import and symbol lines only, proven by the script.
- **`design.md` is background.** Where the record and the design differ, the record wins; where the record is silent, the design's reasoning stands.

## Comments

**2026-09-08 — sliced into ten tickets (`issues/`), and what the measurement corrected.** Every count below was taken on the tree as it stood after CM-4 merged its branch work, not from this spec's figures.

*Corrections to the spec, none blocking, each shaping a ticket:*

1. **Eight external consumers, not four.** The spec counted files importing the old package alone; with workspace and membership inside the unit, the consumers are the invitation service and its trip-membership controller, the join service and its card service, the poll service, and the transport module's two listeners and subscription resolver. Their calls size **MembershipApi at seven** — admit, isMember, membersOf, workspaceIdOf, itineraryIdsByWorkspace, isArchived, itineraryIdsInSightOf — and add **three to TripApi**: teaserOf, titlesByIds and the share card's currentVersion. The spec's `owner` has no outside caller and is not published.
2. **The websocket frame tests are not unedited.** Both import the topic class for its three type-string constants; when that class dies they take a **renamed-symbol edit** to the transport module's event-type home. Seam 1 permits exactly this; seam 3's "unedited" overstated. The frames themselves stay byte-identical, and those tests remain the proof.
3. **The trip controller reaches into the content half.** Its `preview` route calls the published-itinerary service, which stays — so a moved controller would name the old world. Preview lifts out to the staying controller **before** any move (ticket 01), which round 2 Q8 already implied.
4. **The trip-membership controller straddles the boundary.** It lives in the invitation package, carries both roots, and drives the membership service for the roster and the four ownership-offer routes; neither api list in this spec carried the ownership acts. **Founder ruling at slicing: split the controller** — those five routes travel with the ownership slice; MembershipApi stays reads plus admit.
5. **`TripUnarchived` has no consumer** — unarchive calls nothing in any other module. **Founder ruling at slicing: recorded, not built**, per ADR-038's rule that an event is built where a consumer exists; trigger, the first consumer. Five events ship.
6. **Today's trip controller is destruction-only** and collides with the rename target — renamed at ticket 01.
7. **`MembershipArrived` has three publishers**, each immediately after admission; the publish folds into `admit` (ticket 03), leaving one.
8. **The expand phase needs no window.** Old-world classes may implement `trip.api` (the permitted direction), so the interfaces and events land and every consumer cuts over while nothing has moved (tickets 01–03); the two windows live only from ticket 04 to ticket 07.
9. **"The client repository is renamed now"** (grilling round 3 Q2) was done at CM-3 — the client holds `tripRepository` and no `itineraryRepository` — so *Mobile: nothing* holds.

*Owner rulings owed at review — both confirmed at slicing:* the order (events → workspace → the trip's own slices → plan, editing, history → ownership and the windows close → the facade retires → the rename → the gate), and the rename inside this PR as ticket 09.
