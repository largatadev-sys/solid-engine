Behavior spec
1Search — input spec
Entry: the landing bar is a button; tapping pushes full-screen search mode with keyboard up and cursor focused. Back gesture / Cancel restores landing state.
Input: trim whitespace; min 2 chars before querying; max 80 chars; debounce 300ms; cancel in-flight request on each keystroke (latest-wins).
Suggestions: grouped — Destinations, Itineraries, People (max 3 each, "See all" per group). Empty query shows Recents (last 8, deduped, tap ✕ to remove, Clear all) + trending searches.
Submit: keyboard "Search" or suggestion tap → results screen; query saved to recents on submit only, not per keystroke.
2Landing carousels
Trending: free horizontal scroll with start-snap and a peek of the next card (cards 150px, no paging). Tap → destination page (itineraries filtered to it). Ranked by trips created in last 30 days; cached, refreshed on pull-to-refresh.
Recommended: snap carousel, 310px cards with ~24px peek — replaces the Figma full-width pager (peek advertises swipeability; the dots alone don't). Dots update on scroll; beyond 8 items append a "See all" end card instead of more dots.
Both: directional lock vs. vertical feed scroll (same rule as Home); scroll positions preserved on tab switch.
3Category chips
Model: single-select, "All" = no category filter. Selected chip = accent fill (Figma's gray #B3B3B3 reads as disabled).
Behavior: tap re-queries immediately (no Apply needed); selected chip auto-scrolls into view; row h-scrolls with directional lock.
Sync: chips and the filter sheet write the same filter state — a category picked via chip shows selected if the sheet later adds categories, and Reset clears both.
While loading: chips stay interactive; result list shows skeletons; rapid taps cancel the previous request.
4Filter sheet — state spec
State model: draft copy of applied filters; edits mutate the draft only. Apply commits; dismiss (scrim tap, drag down, back) discards the draft — no silent partial application.
Filters: destination (typeahead, single), duration (presets 1–3 / 4–7 / 8–14 / 15+ days — replaces the dual slider, which is imprecise at 345px for a 14-step range), trip type (multi), category (multi, mirrors chips).
Live count: Apply button shows "Show N itineraries", updated via debounced count query on each draft change — prevents zero-result dead ends.
Reset: visible only when filters differ from defaults; resets draft, needs Apply to commit.
Badge: filter button shows the count of non-default filter groups.
5Results list
Header: search bar + chip row stick to the top; count line ("67 itineraries") + sort control (Top rated / Newest / Price ↑↓) scroll with content.
Pagination: cursor-based, page 20; fetch at 5 cards from end; 2 skeleton cards while loading; inline Retry row on failure.
Card tap: → itinerary detail. Bookmark on the cover saves to Trip ideas (optimistic, toast + undo). Author row → profile.
Data note: results and chips must reflect the query scope — searching "Japan" scopes chips + filters to that destination set, and the count updates with every chip tap.
6Data contracts
ItineraryCard { id, title (≤60ch, ellipsize 1 line), coverUrl, location {city, country}, days:int, author {handle, avatarUrl}, rating:float|null, reviewCount:int, price:int|null, currency }

Filters { q?, destinationId?, duration? ∈ {1-3, 4-7, 8-14, 15+}, tripTypes: [], categories: [], sort = "top_rated" }
Display rules: rating hidden + "New" tag when reviewCount < 3 · price null → "Free itinerary" · currency from itinerary, not viewer locale (₱ vs ¥) with converted hint later.
Edge cases
No results: illustration + "Nothing for 'Japan' with these filters" + one-tap "Clear filters" (keeps the query) — never a blank list.
Search error / offline: inline banner with Retry; keep last good results visible rather than wiping the list.
Zero-count Apply: button reads "No exact matches — show closest" and relaxes the least-restrictive filter, or stays disabled; team choice, but never applies into an empty screen.
Slow images: destination-tinted placeholder gradient; failed load keeps gradient + title (cards never collapse).
Long content: titles ellipsize at 1 line; location + days truncate before rating; price never wraps.
Keyboard: suggestion list scrolls under keyboard inset; tapping a result dismisses keyboard first (no ghost taps).
Stale recents: a recent search referencing a deleted itinerary still runs as a plain query — recents store strings, not ids.
Rapid chip taps: requests are cancellable; count and list always reflect the last selection (sequence numbers on responses).
Deep link: results screen is addressable (query + filters in route params) so shared searches restore exact state.
Consistency flags: this Figma frame introduces a fourth accent (#FF751F) on top of #FF5A3C / #D96C4A / #EA580C — the token decision from the Home spec applies here too. It also labels the Trips tab "Trip Workspace" in one frame and "Trips" in another, and uses two different search placeholders; the mock above unifies all three.
