Chat tab — group planning thread, pull-exact spec with live demo
The in-trip group chat for planning, one thread per trip, text only. New feature — nothing shipped yet; flagged unspecced in the audit. Built on the workspace tokens (src/theme/workspaceTokens.ts): accent #EA580C, ink #1C1917, muted #78716C, hairline #E7E5E4, wells #FAFAF9 / #FFF7ED. Frame 0 (bottom right) is a working thread + composer — type, send, and (with the Fail next send tweak) walk the failed-send recovery. It runs the exact motion contract below.
Calls made beyond the brief (UX)
1. My bubbles are the warm tinted well (#FFF7ED, 1px #FED7AA), not solid accent — planning messages run long, ink-on-well reads better than white-on-orange at paragraph length, and accent stays reserved for the one action on screen (Send). 2. Avatar + handle render once per sender group, top-aligned; grouped bubbles sit 2px apart, groups 14px. 3. The character counter is invisible until 1,900; it never nags mid-message. 4. A failed message holds its place in the thread at 55% opacity — no modal, no toast, no reflow. 5. Composer grows to 4 lines then scrolls internally; the thread never loses more than 4 lines to input.

Component contract — normative
C1 · Thread + grouping
One thread per trip, all members, text only, newest at bottom, list bottom-anchored (inverted FlatList). Consecutive messages from one sender within 5 min form a group: avatar + handle once, bubbles 2px apart, last bubble gets the 6px sender-side corner. Inter-group gap 14. On new content while scrolled up: keep position (no jump), quiet "↓ New messages" pill, accent text on white, hairline border — the only new-message affordance in the feature.
C2 · MessageBubble
Text 14/19 #1C1917 both sides, max-width 256, padding 9×13, radius 18. Others: #FAFAF9 + 1px #E7E5E4, 28px initials avatar (stable per-member tint from the profile palette), handle 11/600 muted (e.g. @mayasantos). Mine: #FFF7ED + 1px #FED7AA, right-aligned, never an avatar or handle. Long-press: copy text (platform sheet) — nothing else.
C3 · Time + date
Centered timestamp 11/600 #A59E99 only when the gap to the previous message is ≥ 20 min. Date separator (hairline · label · hairline, same type) between calendar days; "Today" / "Yesterday", else "Tuesday, March 3". Never a per-bubble timestamp.
C4 · Composer
Docked bottom, hairline top. Field #FAFAF9/#E7E5E4 radius 20, placeholder "Message…" #A59E99. Send = 36px circle, disabled until non-whitespace text (#F5F5F4/#A59E99 → #EA580C/white, pressed #E8613A). Grows to 4 lines then scrolls internally — no persistent scrollbar: the platform's transient scroll indicator only (web: scrollbar-width: none). Counter appears at 1,900 chars ("1,968 / 2,000", 11/600 #A59E99), #C2410C at cap; input hard-stops at 2,000. Draft persists per trip across tab switches. Send clears the field immediately (optimistic append).
C5 · Failed send
Optimistic bubble dims to 0.55 on failure; beneath it "Couldn't send" 11/600 #B91C1C + Retry (accent) · Discard (muted), 12/600 text actions with 44px hit areas. Retry restores opacity and re-attempts in place; Discard removes the bubble. Never a modal, toast, or auto-retry.
C6 · Empty + read-only
Empty: 64px #FAF9F6 glyph well + one muted line "Say hello — the plan starts here."; composer present and auto-focused. Archived trip: thread normal, composer replaced by the notice bar "This trip is archived — chat is closed." (#FAFAF9, 13/18 muted, centered). No input anywhere on archived trips.
Ruled out — must not render anywhere: read receipts, delivered/seen ticks, presence dots, typing indicator, unread badges or tab counts, reactions, reply-threading, mentions, and any attachment/camera/photo affordance. Chat is text-only by design.
Motion contract — normative, native-first
M1 · Message entrance (sent + received)
New bubble fades in + rises 8px, 150ms ease-out — opacity + translateY only, Animated.timing with useNativeDriver: true. No spring, no scale — chat entrances are frequent; keep them quiet. Same value for incoming messages. History loaded on scroll-back renders with no animation.
M2 · Send button state
Disabled → enabled crossfades fill + glyph color 150ms ease-out (the shared state-change value). No pop, no scale on send.
M3 · Composer growth
Field height animates 200ms ease-in-ease-out per line added/removed up to the 4-line max (LayoutAnimation.easeInEaseOut; the thread above rides the same layout pass). Web (react-native-web): explicit CSS height transition, same 200ms — LayoutAnimation is a no-op there (same fallback as Profile M2). Keyboard: platform keyboard animation, never custom timing.
M4 · Failed send + recovery
On failure: bubble opacity 1→0.55 150ms; error row fades in 150ms (no rise — it's an annotation, not a message). Retry: opacity back to 1 over 150ms, error row fades out. Discard: bubble + row fade out 150ms, then the list closes the gap with the 200ms layout value. Counter at 1,900: fades in 150ms, no movement.
M5 · Press feedback
Send, Retry, Discard, "New messages" pill: opacity 1→0.85, 100ms in / 150ms release — the shared app value.
Nothing else animates. No scroll-driven effects, no avatar pops, no bubble springs. All motion is transform/opacity, native driver. Reduce Motion: M1 entrance and M3 growth jump-cut; the 150ms opacity fades (M2, M4) stay.
Shared vocabulary (app-wide, from Polls)
color/opacity state change 150ms ease-out · marker/icon entrance pop 200ms cubic-bezier(0.34,1.56,0.64,1) (unused here — deliberately) · layout growth/collapse 200ms ease-in-ease-out · progress/travel 300ms · press 100ms in / 150ms out. Chat uses only the 150ms, 200ms-layout, and press values.
