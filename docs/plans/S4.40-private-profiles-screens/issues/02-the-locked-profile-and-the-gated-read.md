# 02 — The locked profile and the gated read by address

**What to build:** a non-follower opening a private profile sees the header, four inert stat cells, the pill and one **sealed-postcard notice** — no tabs, no chip, no published showcase, nothing tappable but the pill. An approved follower sees the full S4.37 profile. A gated read reached by address — a followers or following list, or a per-trip diary opened from an old feed card or a shared link — renders the same notice with the traveler's first name as the one way to their profile, and never a retry link (spec decisions 3, 4, 5, 11; canvas frames 1a–1d and 7).

**Blocked by:** 01.

**Status:** ready-for-agent

- [ ] **The notice component**, in the profile's empty-state anatomy: 48px cream circle holding the **sealed-postcard glyph** (the SVG paths read from the canvas markup, added to the icon set), title **"{First name}'s postcards are for approved followers."** 15/700, support **"Follow to ask. {First name} decides who's in."** 13 muted, max-width 240. Two modes: on the profile nothing in it is tappable; in **link mode** only the first name is tappable (the canvas's terracotta with a 35%-alpha underline, offset 3px) and opens that traveler's profile through the existing open-traveler-profile hook.
- [ ] **The locked projection of the public profile**: when the subject is private and the viewer's relation is not `following`, the screen renders the identity block **without any chip**, the four stat cells **all inert** (no destination, no press state), the pill, and the notice as the **last element** — no tab row, no Diary or Itineraries pane, no published showcase, whether or not the traveler has published anything (frames 1a–1c differ only in the Published cell's number). No diary or showcase query is issued for the locked page, so no `PROFILE_PRIVATE` is ever fetched there. A `requested` viewer sees the same page with the pill in its third state.
- [ ] **The open projection is untouched**: an approved follower, or any viewer of a public profile, sees the S4.37 screen exactly — tabs, pressable Followers and Following cells, diary sections, and the Follows-you chip as shipped (decision 4: the canvas draws none on 1d because its subject does not follow the viewer; nothing is retired).
- [ ] **Gated reads by address**: on the follow-list screens, a `PROFILE_PRIVATE` answer renders the notice in link mode in place of the retry link, and every other error keeps the retry; on the per-trip public diary screen, a `PROFILE_PRIVATE` answer renders the notice in link mode under the trip-title header, and every other error keeps today's message. Branch on the error's code, never its status.
- [ ] **A copy defect fixed while there:** the public diary tab's failure line reads "Could not load your diary" on someone else's profile; it now names the traveler in the S4.36 first-name style. One line, in a file this ticket edits anyway; recorded so it is not mistaken for scope creep.
- [ ] **Jest:** the locked-profile projection as a pure module — inputs `visibility` and `viewerRelation`, outputs which sections render and which cells open — with every cell of the matrix asserted; a structural guard that the notice is mounted at its three hosts (the profile, the follow lists, the per-trip diary), sabotage-checked by removing one mount. Prior art: the public-profile suite's structural cases.
- [ ] **Playwright, web:** **t1 = private owner, t2 = approved follower** (t2 follows before t1 flips, since going private keeps followers), **t3 = stranger**. t3 on t1's profile: the header and four cells render; the Followers and Following cells do nothing on tap (the URL does not change); no "Diary" or "Itineraries" text; no published rows although t1 has a published trip; the notice text present; the pill is the only control below the header. t2 on t1's profile: tabs, the Following pill, the diary section. t3 by address: t1's followers route → the notice with the linked name → tap → t1's profile; a per-trip diary route by t1 → the notice. t1 with nothing published: the same layout, no empty showcase section.
