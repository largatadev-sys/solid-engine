# 04 — The Follow requests list

**What to build:** a private owner opens **Follow requests** from the Account screen and meets a list of everyone who asked, each row with **Approve** and **Decline**; either removes the row at once and puts it back with a toast if the server refused; the empty state says so when nobody is waiting; the row on the Account screen exists only while the profile is private (spec decisions 8 and 9; canvas frames 4a/4b, contract C2, motion M2 and M3).

**Blocked by:** 03.

**Status:** ready-for-agent

- [ ] **Repository and queries:** the inbox as an infinite query in cursor pages of 20, fetching five rows from the end (S4.37's list rule), the `nextCursor` handed to react-query as-is (the null-cursor trap); approve and decline mutations keyed by the requester's traveler id, invalidating the inbox, the own stats and the follow lists on settle. The list revalidates on focus through the shared helper.
- [ ] **The screen**, a new route in the Profile group: pushed screen titled "Follow requests" with the back target, **no count line**. Each row: 44px avatar, name 15/700, handle 13 muted, a third line **"Asked {ago}"** 12 muted, and two trailing controls — **Approve** (36px filled pill, white 13/700, padding 0 16) and **Decline** (text button, muted 13/700). Row tap opens the requester's profile through the existing open-traveler-profile hook. **M2** on entry: fade + 6px rise, 200ms, 40ms stagger, first 8 rows; later pages append unanimated.
- [ ] **The ago line** reuses the invitation card's ago grammar and **extends it with weeks** ("1w ago", "2w ago"), which the canvas draws and the helper does not yet produce — with the helper's tests extended.
- [ ] **Optimistic in both directions:** Approve and Decline remove the row at once with **M3** (fade + 6px drop over 200ms, no stagger, the list closes the gap); on failure the row is restored with M2 and the toast reads **"Couldn't approve @handle"** or **"Couldn't decline"**; reaching zero rows swaps in the empty state with M2. **No confirm on Decline.** Under Reduce Motion every one of these is a 120ms opacity swap.
- [ ] **The empty state**: the person-plus glyph from the canvas markup in the 48px cream circle, **"No requests right now"** / **"When someone asks to follow you, they'll show up here."**
- [ ] **The Account row** "Follow requests" (chevron) sits between Private profile and Sign out and renders **only while the profile is private**; going public drops it with M3; going private adds it back with M2.
- [ ] **Jest:** the ago helper's weeks; the Account rows rule extended (the row only while private); the optimistic list state — remove, restore, empty — as a pure module in the removal module's queue style; the copy.
- [ ] **Playwright, web:** **t1 = private owner, t4 = requester, t3 = a second requester**. t4 asks through the API; t1 opens Account → Follow requests → t4's row with its "Asked" line → Approve → the row leaves → the server reads t4's relation as `following` → t4's browser reads Following on t1's profile with the full page. t3 asks; t1 declines → the row leaves → the server reads `none` → t3 reads Follow and can ask again. With both gone the empty state renders. A refused approve (the route intercepted to answer 500) restores the row and shows the toast. A public t1 has no Follow requests row on the Account screen.
- [ ] Process gates: full Jest before the push that adds the route; the Playwright list check.
