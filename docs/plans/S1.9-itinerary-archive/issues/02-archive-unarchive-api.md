# 02 — Archive and unarchive end-to-end on the API

**What to build:** the owner takes a trip out of circulation and brings it back, at the API — and one act cleans up everything transactionally: the lease is released, pending invitations and offers void, the list forgets the trip by default and remembers it on request. Demoable end-to-end: archive a trip and watch the lease vanish, the pending invite void, and the list split; unarchive and watch the state come back right.

0. **Answer the module-placement question first** (spec §Backend scope flags it): the archive operation touches `workspace` (the state row), `itinerary` (the lease release), and `invitation` (voiding). S1.5's precedent: the operation goes where it reaches every side by service interface without closing an ADR-011 package cycle — its `membership` module was created for exactly this shape (it already reaches `workspace` and `itinerary`), so joining it is the default; record the decision and its cycle check in this ticket's comments before code.
1. **Domain — archive:** caller's resolved `Membership` in, owner check on the capability object, never inline (Artifact 03). Legal from **any** itinerary state — `draft`, `active`, `completed` (spec decision 8). In one transaction: workspace → `ARCHIVED` · any live edit lease released via a **holder-agnostic** sibling of `releaseHeldBy` (the existing method filters by holder, which the archiving owner does not know; delegation beware — the S0.2 self-invocation gotcha is documented on `releaseHeldBy` itself) · every `PENDING` invitation and any `PENDING` ownership offer → `VOIDED`. Already-archived → the conflict subtype carrying `ILLEGAL_STATE_TRANSITION`.
2. **Domain — unarchive:** owner-only, same shape. Restores the state **derivable from the itinerary** — `COMPLETED` if the itinerary is `completed`, else `ACTIVE` — recomputed, never remembered (no "previous state" column, spec decision 8). Nothing is resurrected: no lease, no invitation, no offer (spec decisions 12–13). Unarchiving a live trip → 409.
3. **`InvitationStatus` gains `VOIDED`** — additive terminal value (verified absent today); the enum javadoc records the three-way split (`revoked` = the owner's act · `declined` = the target's · `voided` = the system's — the split `OwnershipOfferStatus` made first).
4. **Endpoints (additive):** `POST /v1/itineraries/{id}/archive` · `POST /v1/itineraries/{id}/unarchive` — 200 + updated itinerary, no request body (S1.7's action-endpoint idiom). Ladder S1.5-ordered, **authority before state**: 401 · 404 guard-mask (non-member) · 403 `NOT_PERMITTED` (member, not owner — the shipped code; S1.7's comment 1 is the standing warning against minting a new one) · 409 `ILLEGAL_STATE_TRANSITION`. The itinerary read model exposes the archived fact (the projection, spec decision 2) — additive response field.
5. **The list:** `GET /v1/itineraries` gains `?archived=true`, **default false** — today's behaviour preserved exactly (ADR-008). The filter narrows the membership→itinerary-ids step, never the keyset page: S1.6's `id < cursor` seek semantics untouched (spec decision 10).
6. **Analytics:** `itinerary_archived` / `itinerary_unarchived`, after commit only, none on a 409 (spec decision 15).
7. **Tests:** one IT per ladder row for both endpoints, archive from all three itinerary states (spec ACs 1–2) · unarchive restores `COMPLETED` vs `ACTIVE`, 409 on a live trip (AC 3) · lease released at archive, absent after unarchive (AC 6) · invitation + offer `VOIDED` transactionally, neither returns on unarchive (AC 7) · list splits by the flag, keyset paging asserted across both views (AC 11) · events after commit (AC 12) · an authority-before-state test in S1.7's shape (a member archiving an archived trip answers 403, not 409 — a 409 would leak lifecycle position to someone without standing).

**Not in this ticket:** the write fence (`TRIP_ARCHIVED` — ticket 03; until then archived trips accept writes on the feature branch, an accepted intermediate state) · any mobile surface (ticket 04).

**Blocked by:** 01 — the column, the mirror, and the backfill.

**Status:** done

- [x] Archive legal from `draft`, `active`, `completed` — three trips, three 200s (spec AC 2)

## Comments

**2026-07-28 — done. 16 ITs green (10 contract + 6 list/analytics).**

1. **Module placement: `membership`, and the cycle check nearly went the wrong way.** A first grep for `com.largata.membership` inside `invitation/` **hits** — which reads as "`invitation → membership` already exists, so `membership → invitation` closes a cycle" and would have ruled out the correct home. The hit is `invitation/web/TripMembershipController`, a *controller* composing two services for URL cohesion (S1.5's deliberate choice, "one place answers `/members`"). `InvitationService` itself imports nothing from `membership`, so the service layers form a clean DAG: `membership → {workspace, itinerary, invitation}`, none pointing back. Recorded because the S1.5 comment warns about exactly this trap from the other direction, and the discriminating check is *which layer* holds the import.
2. **`OwnershipOffer.voidBecauseTargetDeparted` was renamed `voidBySystem`.** It had one caller (departure) and was named for that caller's reason; archive is the second, and a method named for one trigger reads as a bug at the other's call site. Same outcome, same status, two triggers.
3. **`archived` is a boolean on the wire, beside `state` — not a fourth `state` value.** The grilling's decision 2 in code: archive is on the *workspace* machine and is orthogonal to the itinerary's, so a trip can be `completed` and archived at once and one enum could not say both. Under ADR-008 an `"archived"` state value would have been permanent.
4. **`ItineraryPlan` gained the flag rather than the controller composing it per call site.** The read-model is the honest home for a value assembled from two modules — it is built per request and stored nowhere, so the aggregate never pretends to own a column it cannot see (ADR-002).
5. **A planned `findArchivedAmong` bulk query was written, then deleted before commit.** In the list, every row carries the same archived value as the *request* that asked for it — the filter guarantees it — so the flag is the request parameter and a per-page lookup would have been a query with no reader. Its first draft also had a real cardinality bug worth recording: selecting the itinerary id off `Membership` returns one row **per member**, so a 4-person archived trip would have appeared four times; the workspace is the 1:1 the question needs.
6. **HQL has no boolean-expression-as-value form.** `WHERE (m.workspace.state = …ARCHIVED) = :archived` is a parse error that surfaces as a *context load failure* across every test in the class — ten errored tests, none of them about the query. Split into `findItineraryIdsIn` / `findItineraryIdsNotIn`.
7. **A stale `.class` file made `mvn compile` report success while the app threw at runtime.** `createWithPlan` still held an IDE-written `Unresolved compilation problem` stub for the `ItineraryPlan` arity change; Maven saw a fresh timestamp and skipped it, so the failure appeared as a `java.lang.Error` inside an HTTP request. `rm -rf target/classes target/test-classes` before `test-compile` is the reliable check — the "green everywhere except where it runs" shape again.
8. **The lease release needed a holder-agnostic sibling** (`releaseAnyHold`), because `releaseHeldBy` filters by holder and the archiving owner cannot see who holds it. Deliberately not delegating to its sibling: that would be a self-invocation, which silently drops the propagation of the called method (the S0.2 gotcha `releaseHeldBy`'s own javadoc records).
