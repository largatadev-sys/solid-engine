Lifecycle after this rework
Upcoming — Start Trip → Ongoing — Complete Trip → Completed
One-way ladder, one tab per rung. Planning happens inside Upcoming (the old Draft state folds in; Finalize Itinerary is no longer a rung). Publish remains an act on a Completed trip, shown as the card's Published badge — not a state. Dead labels: Draft, Ready, Active — must not render anywhere. No undo: Step-back confirms and wording are deleted.

Component contract — normative
C1 · Tab row
Exactly three tabs, ladder order Upcoming | Ongoing | Completed — fixed, all always visible even when empty. Equal-width, in-page (not the navigator). Active: 700 weight #1B263B + 3px #D96C4A underline; rest: 400 weight #5C6470. No counts, no icons, no swipe-between-tabs gesture.
C2 · Adaptive landing
On entering the Trips tab: land on Ongoing if it holds ≥1 trip, else Upcoming. Never Completed. Within a session the user's last-selected tab wins over the adaptive rule.
C3 · Trip card
Exactly five slots: 76px cover thumb (r12) · title (1 line, ellipsized) · destination line · optional Published pill (right-aligned) · optional amber Currently being edited advisory. Never: lifecycle badge, date overline, draft subtitle, or the words Draft / Ready / Active. Whole card is the pressable → Trip Workspace (published + not archived → published view, as tripRowDestination today).
C4 · Empty states + create
One line per tab (frame 4 copy is normative). Create = the Plan a Trip bar (51px, accent, r4), pinned to the bottom of the Upcoming tab only — populated and empty alike. Ongoing and Completed carry no create entry anywhere; the shipped always-on CTA bar (all sections) is narrowed, not removed.
C5 · Confirmation drawers
One shared component, two wordings, opened only by the ladder CTA inside the trip screen — never from a list card. Anatomy top-to-bottom: 36×4 handle · title (22/700) · one-line body (13.5/#5C6470) · primary CTA (51px, #D96C4A, r4) · quiet text cancel. Scrim rgba(27,38,59,.55) (colors.scrim); tap-scrim and swipe-down dismiss = cancel. No destructive styling — these are forward moves. No undo affordance after confirm; the drawer's question is the safety.
C6 · Archived
Quiet underlined text link Archived trips as the Completed list footer (and on Completed's empty). Archived trips never appear in the three tabs.
Motion contract — normative
M1 · Tab switch
Same contract as Profile M1: underline slides 200ms ease-out (translateX only, native driver); label color 150ms; incoming list fades in + rises 8px 150ms ease-out. Each tab keeps its own scroll offset. Empty states enter with the same fade-rise — no illustration animation.
M2 · Drawer enter / exit — sets the app-wide sheet pattern
Enter: scrim opacity 0→1 200ms ease-out; drawer translateY 100%→0 300ms ease-out (progress-class duration from the shared vocabulary — the travel is long; transform only, native driver). Exit: drawer down 200ms ease-in, scrim out 150ms, overlapped. Native: Animated.timing, never a JS-spring imitation of the keyboard. Web: CSS transitions, same values. Discovery's filter sheet, Fork's sheet, and the dump picker inherit these numbers — write once here.
M3 · Confirm handoff
On Start/Complete: CTA disables at 0.85 opacity while the request is in flight (no spinner inside the button); on success the drawer runs its M2 exit and the workspace state badge crossfades 150ms to the new label. The trip list re-buckets on next visit with no animation — no card flying between tabs, no auto tab-switch.
M4 · Press feedback
Cards, tabs, CTAs, header icons, archived link: opacity 1→0.85, 100ms in / 150ms release — the shared app value. Pull-to-refresh: platform spinner, no custom motion.
Nothing else animates. Card → trip screen navigation uses the navigator's platform push, not a custom transition (the demo's 300ms slide is a stand-in). Badges, advisories, thumbs, empty copy are static. All motion is transform/opacity. Reduce Motion: M1 content rise and M2 drawer travel jump-cut (scrim still fades 150ms so the modal change reads); M4 stays.
Shared vocabulary (app-wide, from Polls)
color/opacity state change 150ms ease-out · marker/icon entrance pop 200ms cubic-bezier(0.34,1.56,0.64,1) · layout growth 200ms ease-in-ease-out · progress/continuous travel 300ms · press feedback 100ms. M2's 300ms enter is the progress-class duration applied to sheet travel — no new numbers introduced.
