5Done. Sheet travels out 200ms, scrim clears 150ms. Draft released. Nothing persists.
DISMISS WITH TEXT IN THE FIELD
Scrim tap or swipe-down with a non-empty description does not discard silently — the sheet stays and the description field flashes its border to #B3261E for 300ms. Only the close X discards, and it discards outright. A frustrated user should not lose the paragraph they just typed to a stray tap.
NAMING
This entry point says feedback, never report. Report is already spoken for by the postcard action sheet, which means reporting another traveller's content. Two different jobs, two different words — the API route keeps its name, the UI does not borrow it.

09 · COMPONENT CONTRACT
What to build
The data layer is already shipped. This is UI on top of useReportDraft, submitReport and failureOf — plus one change to Button and one new icon.
FeedbackBubble
Mounted once in app/_layout.tsx as a sibling above the navigator, inside the safe-area provider. No props. Never rendered per screen — that is how it reaches sign-in, verify-code, onboarding and join.
useReportDraft() — already shipped; mints the draft with the live route segments on press.
useSafeAreaInsets() — bottom inset.
useKeyboardVisible() — new, trivial; drives the withdraw.
useDockedRail() — new context. Screens with a bottom action rail publish its height; the bubble reads it and offsets. Default 0.
Accessibility. accessibilityRole="button", label "Send feedback", 44 target via hitSlop 2. It is the last element in the reading order on every screen, so it never intercepts the first focus.
FeedbackSheet
draft: ReportDraft | null — presence opens the sheet.
onClose: () => void — releases the draft.
Owns type, description, screenshots and one phase of 'editing' | 'sending' | 'failed' | 'sent', plus the ReportFailure returned by failureOf. On failure it also records the field values at the time of the failure, so a non-retryable error can re-enable Send the moment anything actually changes.
FeedbackTypeToggle — two chips, value / onChange. Reuses SelectableChip geometry at 44 tall.
ScreenshotStrip — photos / onAdd / onRemove / invalid. Caps at MAX_REPORT_SCREENSHOTS.
FeedbackFailureBanner — failure: ReportFailure. Renders the message verbatim; never composes its own copy.
FeedbackThanks — onDone.
Changes to shipped components
Button — add an optional busyLabel?: string. When busy and busyLabel is set, render the spinner and the label side by side with gap 10 instead of the spinner alone. Default behaviour is unchanged everywhere else.
Icon — add 'feedback': the existing comment bubble path with a 3.6-unit stem and a dot at 12.4. It has to read as "something is wrong here", not "reply".
Nothing else changes. The sheet chrome, scrim, grabber and press feedback all come from existing patterns. No new colour, radius, spacing step or type ramp entry is introduced by this work.
Contract notes for the implementer
Mint the draft on open, not on send. The captured screen must be the one the user was looking at when they reached for the button.
Hold the same draft across retries. submitReport releases it only on success, and the server deduplicates on reportId — so retry is a replay, and the button never has to hedge.
Do not surface identity. The bearer is attached by the client when there is one. Signed-out reports send no Authorization header and the form looks identical.
The description field takes the ink border, sign-in does not. The multiline field is drawn at colors.inputBorder (#121212) per the brand spec for inputs. Shipped FormField currently renders colors.border (#E2E4E8), which is what the sign-in mock shows. Worth reconciling app-wide, but not as a side effect of this work.
Failure copy is not editable. All five strings come from REPORT_FAILURES. If a new status needs a new message, it belongs in that file, not in the sheet.
