02 · STATES
Four, and one of them is most of the time
40×40 disc (controls.navControl), white surface, 1px colors.border, 18px glyph in colors.accent. Idle is the default state — the button spends its life at 40% and only comes up to full when touched.
Idle
Opacity 0.4 after 2,600ms untouched. Still fully tappable — dimming is not disabling.
Awake
Opacity 1. Entered on touch down, on hover with a mouse, and for 2,600ms after launch.
Pressed
Shipped usePressFeedback — scale 0.97, opacity 0.85, surface to #FAF9F6.
Dragging
Scale 1.08 and the shadow deepens — it lifts off the page it is floating over. Edge rails fade in behind it.
Why this beats a docked button. A fixed bubble has to know about every bottom action rail, every keyboard, every tab bar, on every screen — and it will still be wrong on the screen nobody thought about. A draggable one is wrong exactly once, and then the user fixes it permanently. It also removes the keyboard-withdraw rule entirely: the dock stays put and the user moves it if it is in the way.
What it costs. Discoverability drops when it is at 40% — so it wakes to full on app launch for 2,600ms before settling, once per session. And it is one more thing that can end up somewhere silly. The snap-to-edge and the vertical clamp are what keep that recoverable.

RULES
Horizontal is quantised. On release the bubble goes to the left or right rail — whichever its centre is nearer — at inset 16. It never rests mid-screen.
Vertical is free, then clamped. Anywhere between 12 below the top safe area and 12 above the bottom safe area. It can sit over a tab bar, and that is allowed — the user put it there.
Drag starts after 4px. Below that it is a tap. Same threshold as the Trips swipe, so the two gestures read the same way.
Pointer capture on grab. The drag survives leaving the bubble's bounds, exactly as the swipe-to-reveal row does.
Default position. Right rail, at the bottom of the clamp — where a first-time user expects a floating action to be. It only moves if they move it.
Hidden while the sheet is open. Fades out with the scrim in, back with the scrim out. It must not float over its own sheet.
04 · WEB
The same dock in a mobile browser
The app ships a web build — MobileFrame.web.tsx, the e2e/web suite, and a .web.ts half for every platform-sensitive module. A floating draggable control has more web-specific failure modes than a docked one, so they are enumerated here rather than discovered later.
largata.app
Largata
Desktop web. The app renders inside MOBILE_FRAME_WIDTH 393, centred in a much wider page. The dock is positioned against the frame, not the window — anchoring it to the viewport would strand it in the grey gutter either side.
WEB RULES
Anchor to the frame. The dock mounts inside MobileFrame's own relatively-positioned container, so position: absolute resolves against 393px on web and the screen on native. Never position: fixed — a transformed ancestor silently breaks it.
touchAction: 'none' on the dock only. Without it, a mobile browser treats the drag as a page scroll and the bubble stutters or never moves. Scoped to the 40px disc, so the feed still scrolls normally around it.
Pointer events, not touch events. One code path for finger, mouse and stylus, with setPointerCapture on grab. PanResponder works through React Native Web, but capture is what keeps a fast drag from being dropped when the pointer outruns the disc.
Suppress the click after a drag. A pointer-up that travelled more than 4px must not also fire the tap. Guard on the same threshold the snap uses.
Suppress the long-press menu. onContextMenu → preventDefault, plus user-select: none and -webkit-touch-callout: none. Holding the bubble to move it should not offer to save an image.
WEB DIFFERENCES
Storage. useDockPosition.native.ts uses AsyncStorage, .web.ts uses window.localStorage behind the same typeof window === 'undefined' guard as recentsStore.web.ts. Same shape, same key.
Safe areas are zero on web. useSafeAreaInsets() returns 0s in a browser, so the clamp would run to the very edge. Floor the top and bottom insets at 12 rather than trusting the hook.
The viewport resizes constantly. Mobile browsers collapse and restore the URL bar on scroll, and desktop windows get dragged. Because y is a fraction, re-clamp on layout change and the dock keeps its proportional place instead of drifting under the toolbar.
Hover exists. On a fine pointer the dock wakes on hover and shows cursor: grab / grabbing. Under @media (pointer: fine) the idle fade is skipped entirely — a mouse user is not obstructed by it and the dimming only costs discoverability.
Keyboard reachable. Focusable, with a 2px colors.accent :focus-visible ring at 2px offset. Enter and Space open the sheet. Arrow keys nudge it 24px and Tab order puts it last.

06 · WIRING
What to build
FeedbackDock
Mounted once in app/_layout.tsx as a sibling above the navigator, inside the safe-area provider and inside MobileFrame. No props. Never rendered per screen — that is how it reaches sign-in, verify-code, onboarding and join without any of them knowing it exists.
useReportDraft() — shipped. Called on press, so the draft carries the route the user was actually looking at.
useSafeAreaInsets() — feeds the vertical clamp, floored at 12 for web.
useDockPosition() — new, platform-split. Reads and writes feedback.dock.position as { edge: 'left' | 'right', y: number }, y a 0–1 fraction of the clamped range. Defaults to { edge: 'right', y: 1 }.
Animated.ValueXY for the live drag, Animated.spring for the snap. Native-driven on device; the web build falls back to the composited transform, which is why the drag writes translate and never left/top.
Accessibility. accessibilityRole="button", label "Send feedback", 44 target via hitSlop 2. Last in the reading order on every screen. Screen readers and keyboards get the tap and the arrow-key nudge — the drag is a pointer affordance, and the default position is already sensible.
The tap, end to end
1Release under 4px of travel. newReportDraft(segments) mints the id and resolves the screen string through SCREEN_LABELS.
2Dock fades out with the scrim in. The sheet takes over from here.
3On send, submitReport(draft, fields). On any throw, failureOf(thrown) — never a raw error.
4Hold the same draft across retries. It is released only on success, and the server deduplicates on reportId — so a retry is a replay, and the button never has to hedge.
5Sheet closes, dock fades back in awake, then idles after 2,600ms.
Icon. One addition — 'feedback': the existing comment bubble path with a 3.6-unit stem and a dot at 12.4. It has to read as "something is wrong here", not "reply".
Naming. The control says feedback, never report — PHOTO_SHEET_REPORT already means reporting another traveller's postcard. The API route keeps its name; the UI does not borrow it.
The sheet the dock opens — form, submitting, both error shapes and the thank-you — is specified in Feedback Entry & Report Flow. Only the placement sections there are superseded by this file.
