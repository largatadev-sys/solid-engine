# 01: The status answers — `WorkspaceState` is open or archived, the wire keeps `completed` as a projection, `Trip` stops carrying `published`, and V58 makes the schema say so

**What to build:** the two entities tell the truth about the two facts they own, and nothing a client reads changes. `WorkspaceState` becomes `ACTIVE | ARCHIVED` — the `COMPLETED` value is a stored copy of the lifecycle's (unarchive has to be *told* what to restore; the lifecycle transitions write it as a side effect) and it leaves: lifecycle transitions stop touching the workspace, unarchive takes no argument, the workspace exposes whether the room is open. The wire's `workspaceState` — which the client's chip reads for `completed` — keeps its three values as a **projection** computed where the response already holds both facts: `archived` when the room is closed, else `completed` when the lifecycle is completed, else `active`. `Trip` loses its publication flag, its stamp, their writers and reader, and the entity-level `requireUnpublished` that read a column nothing has written since CM-5 and always passed; the six readers that always answered `false` are re-pointed at the publication port or deleted, and the two log lines stop printing `published=`. Migration **V58** rewrites `COMPLETED → ACTIVE` on the workspace, adds a `CHECK` on the two remaining values, and drops the itinerary's two dead publication columns — destructive by design, the shape the founder accepted at S4.25, with the yes on the record (grilling Q4, Q5). Spec decisions 12–14.

## Comments

**Closed 2026-09-18.** The three facts and what proves each:

- **`WorkspaceState` is `ACTIVE | ARCHIVED`.** `COMPLETED` is gone from the enum, `markCompleted`/`markActive` are gone from the entity and the service, `complete()` and `reopen()` no longer touch the workspace at all, and `unarchive()` takes no argument. `TripService.isCompleted` died with the boolean it existed to feed — it had exactly one caller, `unarchive`'s argument. `WorkspaceStateTest` pins the two values, both sides of the one fact, and the stored spelling.
- **The wire is byte-identical.** `WorkspaceStateProjection.of(lifecycle, archived)` in `trip.api` is the single definition; both sites that had to change already held the lifecycle locally (`TripResponse.of` reads `itinerary.state()` eleven lines above; `TripFactsService.entryOf` reads `trip.state()` four lines above), so no plumbing was added. `MyTripResponse` copies the string and needed nothing. `WorkspaceStateProjectionTest` walks all six combinations. **Mobile needed no change** — `api.ts`'s union and `WorkspaceChip`'s `'completed'` branch still describe what the server sends, which is the point of a projection.
- **`Trip` carries no publication.** The field, the stamp, `publishTo`, `unpublish`, `isPublished`, `publishedAt` and `requireUnpublished` are gone. `reopen`'s only guard is now `TripService`'s check through the publication port, which was already there and already the real one (line 310 on `dev`). The three API records lost their `published` component — `TripTeaser`, `TripFacts`, `TripPlan` — and **every one of those had zero readers**: `JoinService.isClosed` already asked the port, and `TripResponse` already read `TripPlanTree.published()`, which is the port too.

**Found while measuring, beyond the ticket's list:**

- **`TripRepository` carried ~180 lines of dead publication queries** — 13 methods predicated on `i.published`, including a full second copy of the Discover scope (`ON_THE_STRANGERS_SURFACE`, `DISCOVERABLE`) that `itinerary`'s repository had long since superseded. Zero callers, production or test. They had to go regardless: Spring Data validates JPQL at bootstrap, so `i.published` against a dropped column fails the context for the whole application. `TrendingDestinationRow` was orphaned by their removal and went too. `DiscoveryScopeIsDefinedOnceTest` reads only the `itinerary` repository and was unaffected.
- **`trip`'s `NotCompleteException` was a duplicate of `itinerary`'s `TripNotCompleteException`** — same `ITINERARY_NOT_COMPLETE` wire code, and only the deleted `publishTo` ever threw it. `itinerary`'s is the live one (`ItineraryContractIT` asserts the code through it). Deleted.
- **V32's `idx_itinerary_discovery` was a partial index on `published = true`.** `DROP COLUMN` would have taken it implicitly; V58 drops it by name first so the retirement is a statement somebody chose to write, and the stepping IT asserts its absence.

**The four assertion changes, each with its authority:**

1. `TripArchiveContractIT.unarchiveRestoresCompletedForACompletedTripAndActiveForEverythingElse` → `unarchiveAnswersCompletedFor…` — **the amendment this ticket pre-authorises (Q4)**. It read the raw `workspace.state` column for `"COMPLETED"`; it now asserts `$.workspaceState` is `completed` **on the wire** and that the stored room is `ACTIVE`, which is strictly more than it checked before — it pins the projection and the storage in one walk. The other seven `workspaceStateOf` assertions in that class read `ACTIVE`/`ARCHIVED` and stand unedited.
2. `WorkspaceStateStorageIT.aCompletedTripsWorkspaceStoresCOMPLETED` → `aCompletedTripsRoomStaysOpen_becauseTheLifecycleIsNotTheWorkspacesFactToStore` — the same behaviour change from the storage side (Q4).
3. `ForkContractIT.stampsOf` drops `published_at` from its `SELECT`; the fork test now asserts two null stamps instead of three (Q5). Raw SQL against a dropped column — `BadSqlGrammar`, not a semantic change.
4. `TripTest`'s publication block: four entity tests deleted with the methods they drove, replaced by `theTripKnowsNothingAboutPublication_soItsLifecycleMovesFreely`, which asserts what is now true — a completed trip reopens, because the entity holds no flag to refuse on (Q5).

**The migration, sabotage-checked twice** (`test-compile` in the goal list both times, and the sabotage grepped from the file before believing either run):

- Lower-case `WHERE state = 'completed'` (the V4 trap): the migration itself **failed** on the new `CHECK`, because the unrewritten rows could not satisfy it. A real failure mode, but it proves the constraint rather than the assertions.
- Backwards rewrite, `SET state = 'ARCHIVED' WHERE state = 'COMPLETED'`: **migrates cleanly** — `ARCHIVED` passes the CHECK — and **9 tests ran, 1 failed**, `everyWorkspaceStoringTheLifecycleIsReopened` at the line that owns the rewrite, with the right diagnosis.
