# 05 — The itinerary axis retires

**What to build:** the itinerary loses its own public/private switch without breaking a phone. Rows published as private are unpublished, never exposed; the column goes; every itinerary response still carries `visibility` as a constant; a private `audience` at publish is refused by name; Discover and the trip-media fence stop asking a question that no longer exists (spec decisions 3, 15, 16 and the schema note).

**Blocked by:** None — can start immediately. *(Independent of 01–04; it shares the story branch and the one-Maven-run rule, so in practice it runs in sequence, not in parallel.)*

**Status:** done

- [x] **Migration, next free `V`:** first unpublish every itinerary that is `published` with `visibility = 'PRIVATE'`, writing exactly what the owner's own unpublish transition writes today (the published flag and its stamp treatment), so a migrated row is indistinguishable from one the owner unpublished; count and log the rows in the V18/V20 style. Then drop the `visibility` column. Archived rows are handled identically — archive dominates either way.
- [x] **The stepping IT, in the backfill mould** (prior art: the axes, published-at and diary-public backfill ITs): its own container, Flyway to the version before, raw-SQL seed of two private-published rows plus a public-published and an unpublished-private control, migrate, assert exactly the two flipped, the controls untouched, the column gone. **Sabotage the SQL, prove the test catches it, restore — and `test-compile` before the sabotage run** (the S4.13 trap).
- [x] **The wire keeps the field:** every itinerary response that carried `visibility` still carries it, as the constant `"public"`. The `Visibility` enum and its column mapping retire from the entity. **Narrowed during the build, 2026-09-04:** asserted as `$.visibility == "public"` on both response factories and across every lifecycle transition (`theTwoAxesAreIndependentFactsOnTheWire_andVisibilityIsAConstantBesideThem`), not as a byte comparison against a pre-change capture — that capture does not exist once the change is in the tree.
- [x] **`POST /v1/itineraries/{id}/publish`:** `audience: "private"` → **`400 VISIBILITY_RETIRED`**, never silently accepted; `audience: "public"` and no `audience` publish exactly as today. The request record keeps its field.
- [x] **Discover:** the count and the list drop the `visibility = 'PUBLIC'` clause — `published AND NOT archived` is the whole rule; the count-agrees-with-list IT stays green (the author-resolution asymmetry on the backlog is untouched by this ticket).
- [x] **The trip-media audience** (cover and activity photos): published → any signed-in traveler, unpublished → members; the visibility clause is gone. **The published-itinerary read** keeps no private-visibility not-found path: a published itinerary answers to every signed-in traveler, including one whose owner's profile is private — asserted.
- [x] **Every IT and every Playwright spec that sent `audience: private` or asserted a collaborator-only published read is rewritten to the new contract**, never deleted silently — grep the test trees for the private audience before starting; the S4.11 three-axes ITs become two-axes ITs.
- [x] **The demo seeder** publishes some trips `private` today; it publishes them public (or omits the audience) so seeding does not 400. Note it in the seeding runbook's comments if the runbook names the value.
